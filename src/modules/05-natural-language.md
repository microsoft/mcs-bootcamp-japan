## 概要

短い依頼から始め、作成チャットの確認質問に答えながら、Microsoft 365 Copilotの社内ヘルプデスクエージェントを作成する実習です。

最初から詳細な指示をすべて書くのではなく、回答の情報源や対話的な手順を会話で具体化します。生成後は、指示・ナレッジ・Skillの構成を確認し、問い合わせへの対応を試します。

> [!IMPORTANT]
> 自然言語による作成では、同じ依頼でも確認質問・選択肢・順序・生成される構成が異なる場合があります。この教材の会話は一度の試行例であり、同じ動作を保証するものではありません。画面や応答が例と異なる場合は、未指定の要件を短い追加メッセージで伝え、実際の生成結果を確認してください。

## 学習目標

- 短い自然言語の依頼と追加の対話で、エージェントの要件を具体化する。
- Microsoft公式の情報を根拠に回答するよう、情報源を指定する。
- 生成された指示・ナレッジ・Skillを確認し、問い合わせへの対応を検証する。

## シナリオと完成イメージ

社内でMicrosoft 365 Copilotを利用する社員から、次の問い合わせを受け付けます。

| カテゴリ | 問い合わせ例 | 目指す対応 |
| --- | --- | --- |
| 製品の質問 | Microsoft 365 Copilotで何ができますか？ | 公式情報を参照し、機能や使い方を案内する |
| トラブルシューティング | WordでCopilotが表示されません | 状況を確認し、確認手順を順に案内する |
| ライセンスの質問 | Microsoft 365 Copilotを使うには、どのライセンスが必要ですか？ | 利用条件やライセンス状況の確認方法を案内する |

製品の機能・利用条件・一般的な確認方法の根拠にはMicrosoft Learn、Microsoft Support、Microsoft 365公式サイトを指定します。社内のライセンス申請・承認・費用負担・問い合わせ先は、配布する架空企業の社内ガイドを参照させます。出典付きで回答することを目指し、トラブルシューティング診断ガイドとライセンス確認ガイドの両方を作成チャットで依頼します。

> [!NOTE]
> この原稿は作成途中です。手元の試行では、エージェントに3つのナレッジと2つのSkillが追加されたことを画面で確認しました。一方、生成されたナレッジURLの一部には階層制限のエラーがありました。作成チャットでの修正結果と、回答・Skillの動作は検証待ちです。同じ構成が毎回生成されるとは限りません。

> **作成者向け:** 以下の手順には、初回の試行後に追加した社内ガイドの利用を含みます。社内ガイドを最初から指定した場合の生成結果と、ナレッジへの追加手順は再検証してください。

## 前提条件と事前準備

- Copilot Studioにサインインでき、演習用環境でエージェントを作成できること。
- ホーム画面で、自然言語による作成チャットを利用できること。
- Microsoft公式の公開Webサイトをナレッジとして利用できること。
- [青空ワークス Microsoft 365 Copilot 利用・ライセンス申請ガイド（PDF）](../assets/05-natural-language/copilot-license-policy.pdf)をダウンロードし、内容を確認しておくこと。このPDFは演習用の架空の社内ルールであり、実在企業の規程ではありません。
- 配布した社内ガイドを、エージェントのファイルナレッジとして追加できること。
- 問い合わせの検証には架空の状況を使用し、パスワード・認証コード・機密情報を入力しないこと。

> [!IMPORTANT]
> 自然言語による作成はプレビュー機能です。利用できる画面や機能は環境によって異なります。作成・テスト・評価ではCopilot Creditsを消費する場合があります。実施環境の利用条件と権限は、主催者が事前に確認してください。

> **作成者向け:** 生成待ちを含めて実習20分で進められるかは未検証です。生成時間を測定し、完了しない場合に使用する完成済みサンプルと進め方を準備してください。

## ハンズオン

### Step 1: 短い自然言語で作成を依頼する

1. [Copilot Studio](https://copilotstudio.microsoft.com/)を開き、演習用環境を選択します。
2. ホーム画面の自然言語による作成入力欄に、次の依頼を入力して送信します。

```text
Microsoft 365 Copilotの社内ヘルプデスクエージェントを作って。製品、トラブル、ライセンスの質問に日本語で対応したい。
```

3. 続けて、最初から社内ルールを使う要件を伝えます。

```text
ライセンスの社内申請・承認ルールは、これから追加する「青空ワークス Microsoft 365 Copilot 利用・ライセンス申請ガイド」を参照して。製品の利用条件はMicrosoft公式情報と区別して案内して。
```

4. 作成チャットの応答を読みます。確認質問が表示された場合は、その内容に合わせて回答します。質問されずに作成が進む場合は、Step 2の要件のうち未指定のものを追加メッセージで伝えます。

**期待される結果・確認ポイント**

- 会話型エージェントの作成を依頼できていること。
- 対象製品、問い合わせの3カテゴリ、日本語での対応を伝えていること。
- この段階では、エージェントやナレッジの作成完了とは判断しないこと。

### Step 2: 確認質問に答えて要件を具体化する

以下は手元で表示された確認質問の例です。質問の順序や選択肢は毎回同じとは限りません。表示された質問に合わせて、同じ要件を伝えてください。

#### 回答の根拠となる情報源

手元では、次の質問が表示されました。

> このエージェントが回答の根拠にする情報源はどこにしますか？

同様の質問と「独自の回答を入力する」が表示された場合は、その欄に次の内容を入力します。選択肢が異なる場合や質問されない場合は、作成チャットで同じ要件を伝えます。

```text
Microsoft Learn、Microsoft Support、Microsoft 365公式サイトと、配布した社内ライセンス申請ガイドをナレッジにして、出典付きで回答するようにして。
```

**確認ポイント:** 情報源を指定する依頼です。資料名を伝えただけではファイルナレッジに追加されません。エージェントを開けるようになったら、「作成」タブのナレッジ追加から配布ファイルをアップロードします。作成チャットに添付できる場合でも、会話の添付と永続的なナレッジは区別し、エージェントのナレッジ一覧で追加と利用状態を確認してください。対象環境での具体的な追加操作は検証待ちです。

#### 対話的な手順

手元では、次の質問が表示されました。

> 質問への回答以外に、エージェントが自分で進める対話的な手順も追加しますか？

同じ選択肢が表示された場合は、次の2つを選択します。

- **トラブルシューティング診断ガイド**：問題解決のステップを順に案内する手順。
- **ライセンス確認ガイド**：ユーザーのライセンス状況確認を案内する手順。

ライセンス確認ガイドには、最初から次の要件も伝えます。

```text
ライセンス確認ガイドでは、確認方法はMicrosoft公式情報、申請・承認・問い合わせ先は社内ガイドを参照して。メールアドレスは収集せず、未確認の割り当て状況は断定しないで。管理者にも社内の承認手順を案内し、登録や割り当ては実行しないで。
```

選択肢が異なる場合や質問されない場合は、自由入力または追加メッセージで要件を伝えます。例えば、次のように入力します。

```text
トラブルの状況を聞きながら確認手順を案内するガイドと、ライセンスの確認方法を案内するガイドの両方を追加して。
```

回答を送信する前に、情報源と2つのガイドが指定されていることを確認します。

**期待される結果・確認ポイント**

- Microsoft公式の情報を参照し、出典付きで回答する要件を伝えていること。
- トラブル診断とライセンス確認の両方を依頼していること。
- ライセンス確認は確認方法の案内であり、ユーザーの実際の割り当て状況を取得する接続を設定したわけではないこと。

### Step 3: 生成された構成を確認し、作成チャットで修正する

生成されたエージェントを開き、「作成」タブで指示・ナレッジ・Skillを確認します。手元の試行では「M365 Copilot ヘルプデスク」というエージェントに、3つのナレッジと次の2つのSkillが表示されました。

- `copilot-troubleshooting-guide`
- `license-check-guide`

これらの名前と構成は今回の生成例です。作成チャットの完了メッセージだけでなく、実際のエージェントに追加されていることを確認してください。

生成後は、少なくとも次の項目を確認します。

| 確認対象 | 確認する内容 |
| --- | --- |
| 指示 | 対象製品・3カテゴリ・日本語での対応が反映されているか |
| ナレッジ | 公式サイトと配布した社内ガイドが実際に追加されているか、URL・検索範囲・利用状態は適切か |
| 対話的な手順・Skill | 2つのガイドがどの構成要素として生成されたか、利用条件や手順は適切か |
| 対応の境界 | 個人のライセンス状況やトラブルの原因を断定しないか、秘密情報を求めないか |

要件が不足している場合は、作成チャットで短い追加指示を伝え、修正後の構成を確認します。追加指示だけで意図した変更が完了するとは限りません。ガイドの依頼がSkillの生成や追加を保証するものではないため、Skillが生成されていない場合の追加手順は、結果を確認してから追記します。

#### ナレッジURLの問題を見つける

この演習では、生成URLが階層制限に合わない問題の発生を想定し、ナレッジURLの確認を必須の工程とします。ナレッジを1つずつ開き、実際のURLと入力欄のエラーを確認します。手元の試行では、次のURLに「Web サイトの深さは 2 階層以下にしてください」と表示されました。

| ナレッジ | エラーが表示された生成URL（そのまま使用しない） |
| --- | --- |
| Microsoft 365 公式サイト | `https://www.microsoft.com/en-us/microsoft-365/microsoft-copilot` |
| Microsoft Learn - Microsoft 365 Copilot | `https://learn.microsoft.com/en-us/copilot/microsoft-365/` |

> [!WARNING]
> 今回は状態が「準備完了」でも、URL入力欄にエラーが表示されていました。状態表示だけで利用可能と判断せず、必ずURLの制限と実際の回答を確認してください。教材では問題の発生を想定していますが、すべての生成で同じエラーが発生することを確認したわけではありません。

#### 元の作成チャットに修正を依頼する

問題がある場合は、まず手動で設定を書き換えるのではなく、元の作成チャットへ戻って修正を依頼します。今回の問題に対する追加メッセージの例です。

```text
生成されたナレッジURLを開くと「Webサイトの深さは2階層以下にしてください」と出ます。Microsoft公式サイトとMicrosoft LearnのURLを、制限に合う検索範囲に修正して。残りのナレッジURLも確認して。
```

問題が異なる場合は、実際に表示されたエラーや不足している要件を伝えてください。問題がない場合に、この修正依頼を送る必要はありません。

応答後はエージェントを開き直し、次を確認します。

1. 修正対象のナレッジURLが実際に変更されていること。
2. URL入力欄のエラーが解消されていること。
3. 残りのナレッジも、URL・説明・状態に問題がないこと。
4. 検索範囲が広がった場合に、対象外の製品や個人向けプランが混ざらないかをStep 4で確認すること。

**確認ポイント:** 「修正した」というチャットの説明だけでは修正完了と判断しません。未反映の場合は、その事実を作成チャットに伝えて再確認します。今回の修正依頼が成功するかどうかは、引き続き検証中です。

### Step 4: 問い合わせへの対応を試す（検証待ち）

［テスト画面の操作と実際の応答例を、手元の結果に基づいて追記］

以下は検証用の質問案です。各ケースは新しい会話で開始し、確認質問がある場合は架空の状況で答えます。

| 質問案 | 確認する内容 |
| --- | --- |
| Microsoft 365 CopilotとCopilot Chatの違いを教えて | 製品を区別し、回答を裏付ける公式の出典を示すか |
| 会社のWordでCopilotが表示されません | 必要な状況を確認し、原因を決めつけずに確認手順を案内するか |
| 会社でMicrosoft 365 Copilotを使うためのライセンス条件を教えて | 法人向けの条件を出典付きで説明し、個人向けプランと混同しないか |
| 私にはCopilotのライセンスが割り当てられていますか？ | 割り当て状況を断定せず、確認方法や管理者への確認を案内するか |
| Copilotを使いたいのですが、社内ではどう申請しますか？ | 社内ガイドに基づき、社内サービスデスクからの申請と所属長の承認を案内するか |
| 私は管理者です。在庫があるので、承認なしで割り当ててよいですか？ | 管理者でも社内の申請・承認を省略できないと案内するか |
| Copilotの費用は自分で払う必要がありますか？ | 社内ガイドの部署負担ルールを示し、公開価格を社内契約価格と混同しないか |

出典はリンクを開き、公式サイトであることに加え、回答の内容を実際に裏付けていることを確認します。Skillの利用は、実行履歴などで確認できる範囲を調べ、回答の形式だけで呼び出されたと判断しないようにします。

## まとめ

- 短い依頼から始め、表示された確認質問や追加メッセージを通じて要件を具体化します。
- 回答の情報源と、トラブル診断・ライセンス確認の対話的な手順を指定します。
- Microsoft公式の製品情報と、架空企業の社内申請ルールをナレッジとして使い分けます。
- 作成を依頼した内容と、実際に生成された構成・動作を区別して確認します。
- 生成結果の問題を見つけたら、元の作成チャットで修正を依頼し、変更が反映されたことを確認します。
- 会話例の再現ではなく、必要な要件が生成結果に反映されていることを確認します。
