## 概要

### Copilot Credits とは

Copilot Credits は、エージェントやワークフローなどの利用量を測る共通の単位です。AI モデルが処理するトークン、ツールやナレッジの利用、ハーネスによる処理などに応じて消費します。「質問 1 回につき一定量」ではなく、使用するモデル・処理内容・実行回数などで消費量が変わります。

クレジット数は金額そのものではありません。実際の請求額は、前払い・従量課金などの契約条件によって異なります。また、今回利用する Microsoft Copilot ハーネスの消費は、Microsoft 365 Copilot ライセンスには含まれません。実行環境に対して計上され、操作した参加者個人へ直接請求されるわけではありません。

### いつクレジットを消費するか

**公開後だけでなく、開発中から消費します。** 今回の演習では、次の操作が対象になります。

| 場面 | 演習での例 |
| --- | --- |
| 自然言語による作成・修正 | 05 の作成チャットでエージェントやスキルを作成・修正する |
| プレビュー・テスト | 質問して回答やツールの動作を確認する |
| 評価 | 06 の評価を作成・実行・再実行する |
| ワークフローの作成・実行 | 07 の受付ワークフローを作成・実行し、イベント起点で分類・要約する |
| 公開後の利用 | 利用者への回答や、自律的な処理を実行する |

「まだ公開していないから無料」「テストや再評価は無料」とは考えず、開発中から消費を確認します。標準ハーネスとは課金の対象が異なるため、今回の Microsoft Copilot ハーネス向けの説明を参照します。

### 画面でどう確認するか

確認したい範囲に応じて、次の画面を使い分けます。

| 画面 | 確認する内容 | 数値の見方 |
| --- | --- | --- |
| プレビュー | 現在の会話で消費した推定クレジット | 処理直後に確認するための概算値 |
| 評価 | 評価の実行に使用した推定クレジット | 評価の実行・再実行にかかった消費の概算値 |
| 監視 | 公開したエージェントの利用状況・フィードバック・クレジット | 公開して利用が開始されると表示される。反映には時間がかかる |
| Power Platform 管理センター | テナント・環境・エージェント単位の消費や容量 | 管理者が組織全体の利用状況を確認するための情報 |

**監視**は、公開したエージェントがチャネル経由で利用されるようになってから、利用状況を確認する画面です。対象エージェントを開いて**監視**タブを選び、日付フィルターで対象期間を指定します。

未公開の場合は「まだ公開されていません」と表示され、利用状況・フィードバック・クレジットのデータは表示されません。これは、開発中にクレジットを消費していないという意味ではありません。開発中の消費は**プレビュー**や**評価**の推定クレジットで確認し、この実習のモデル比較にも**評価**画面の値を使います。

環境全体などの消費は、管理者が**Power Platform 管理センター → ライセンス → Copilot Studio** で確認します。

### 評価を使ってモデルとコストのバランスを確認する

モデルは、**必要な回答品質を満たせるかを確認したうえで、消費クレジットと応答速度を比較して選びます。** 高性能なモデルを常に使う、または消費の少なさだけで選ぶのではなく、用途に合うかを評価で確かめます。

| モデル選定のポイント | 確認すること |
| --- | --- |
| 処理の難しさに合わせる | 定型的な分類・短い要約では軽量・高速なモデルを候補にし、複数の条件を踏まえる判断や複雑な案内では推論能力の高いモデルも比較する |
| 低消費でも必要な品質を保つ | 正答率や評価スコアだけでなく、社内ルールの順守、出典、確認質問、必要なスキルの使用も確認する |
| モデルの単価だけで決めない | トークン量やツールの利用、やり直しの回数でも消費は変わるため、実際の処理全体で比較する |

06 で用意したテストセットを使い、モデルだけを変更して再評価します。質問・期待応答・評価方法・指示・ナレッジなどの条件をそろえ、評価結果・所要時間・推定クレジットを比較します。スコアだけでなく、個別の応答も読み比べます。

例えば、モデル B の消費がモデル A より少なくても、社内ルールを誤って案内するなら採用しません。一方、両方が必要な品質を満たすなら、消費が少なく応答も速いモデルが有力な候補になります。

推定クレジットは評価実行全体の値であり、そのまま本番の 1 回の回答にかかる費用とは扱いません。また、同じモデルでも実行ごとに結果や消費は変動するため、僅かな差だけで優劣を断定しません。モデル比較のための再評価自体もクレジットを消費します。

## 学習目標

- プレビュー・評価で確認する開発中の推定消費と、監視で確認する公開後の利用状況を区別する。
- 表示された消費情報と実施した操作の関係を考える。
- 同じテストセットでモデル変更前後を評価し、回答品質・所要時間・消費クレジットのバランスを判断する。

## シナリオと完成イメージ

これまでに作成したエージェントを使い、モデルを変更した場合に、回答品質・所要時間・推定クレジットがどう変わるかを確認します。06 のテストセットを再利用し、必要な品質を満たせるモデルを比較します。

エージェントの公開は不要です。監視タブのデータではなく、評価の実行ごとの結果を使います。

## 前提条件と事前準備

- これまでに作成したエージェントを編集でき、評価を実行できること。
- 06 で作成したテストセットと評価設定が保存されていること。
- 対象環境で、比較する 2 つのモデルを選択できること。
- 評価の実行・再実行にも Copilot Credits を消費することを確認しておくこと。

## ハンズオン

### Step 1: 現在のモデルの評価結果と消費を確認する

1. エージェントの**作成**タブで現在のモデル名を確認し、エージェントを保存します。
2. **評価**タブを開き、06 のテストセットを使って現在の構成で評価を実行します。同じモデル・構成・評価設定で実行済みの結果がある場合は、その結果を使えます。
3. 完了した評価の結果を開き、モデル名・評価結果・所要時間・推定クレジットを記録します。06 の評価後に指示やツールなどを変更している場合は、以前の結果をそのまま比較元にせず、現在の構成で実行した結果を使います。

### Step 2: モデルだけを変更して再評価する

1. **作成**タブに戻り、別のモデルを選択して保存します。モデル以外の設定は変更しません。
2. **評価**タブで、Step 1 と同じテストセット・評価設定を使って再実行します。
3. 完了した評価の結果を開き、変更後のモデル名・評価結果・所要時間・推定クレジットを記録します。

### Step 3: 品質と消費のバランスを比較する

1. 変更前後のスコアや合否を比較し、不合格になったケースや、回答内容が変わったケースを開きます。社内ルール・出典・対応範囲など、必要な品質が保たれているか確認します。
2. 所要時間と推定クレジットを比較します。消費が減っても必要な品質を満たさないモデルは選ばず、品質・時間・消費のバランスから判断します。
3. 比較結果を踏まえて使用するモデルを選び、エージェントを保存します。

**期待される結果・確認ポイント**

- 同じテスト条件で、モデル変更前後の評価結果・所要時間・推定クレジットを比較できること。
- 消費の少なさだけでなく、必要な回答品質を満たすかを説明できること。
- エージェントを公開せず、評価画面で開発中の推定消費を確認できること。

## まとめ

- Microsoft Copilot ハーネスでは、公開後の利用だけでなく、作成・テスト・評価でも Copilot Credits を消費します。
- 開発中の推定消費はプレビュー・評価で確認し、公開後の利用状況は監視で確認します。
- モデルは、同じ条件で評価した回答品質・所要時間・消費クレジットを比較して選びます。
