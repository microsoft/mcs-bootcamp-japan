## 概要

基礎①②ではエージェントの中に置くもの（インストラクション、メモリ、Skill）を扱いました。基礎③ではエージェントの外にあるもの（文書、業務システム、Microsoft 365の仕事の文脈）につなぎます。

ナレッジに文書を2つ、ツールにMCPサーバーを2つ追加し、質問を送ります。どの情報源を使うかは伝えません。エージェントが情報源を選び、ツールが失敗してもやり方を変えて進むところを、推論のトレースで確かめます。最後にWork IQを追加し、ナレッジに入れていない社内の資料から過去の事例を探して、メールで知らせるところまで進めます。

## 学習目標

- 役割と範囲だけを書いたインストラクションで、エージェントを作る。
- ナレッジとツールを追加し、どの情報源を使うかをエージェントが選ぶことを確かめる。
- 推論のトレースを開き、ツールの失敗からやり方を変えて進む流れを読む。
- Work IQで社内の資料を探し、頼まれてからメールを送ることを確かめる。

## シナリオと完成イメージ

あなたは、風力発電の事業者 Northgate Energy の設備管理担当者です。Cascade Ridge風力発電所のタービンのテレメトリを見て、作業班を現場に出す必要があるかを判断します。今回の対象は、ギアボックスの振動が4.6 mm/sになっているタービン WTG-114（Aeris 3.2 MW）です。

「4.6 mm/sは問題か」という問いには、1つの情報源だけでは答えられません。

| 情報源 | 種類 | 分かること |
| --- | --- | --- |
| Asset Telemetry MCP（ツール） | システムの値 | いまの測定値、アラーム、過去の推移 |
| Work Orders MCP（ツール） | システムの値 | 起票済みの保守作業 |
| 保守マニュアル（ナレッジ） | メーカーの文書 | 設備の限界値、アラーム コードの意味 |
| 出動基準（ナレッジ） | 自社の文書 | 区分、出動の期限、通知先、起票のルール |
| Work IQ（ツール） | Microsoft 365の社内の情報 | その人が見られる社内の資料、メール |

| Step | 場面 | すること |
| --- | --- | --- |
| 1 | 調査用のエージェントを用意する | エージェントを作り、名前とインストラクションを貼り付ける |
| 2 | アラームが出ているタービンを調べる | ナレッジとツールを追加し、質問を3つ送る |
| 3 | 推論のトレースを読む | 新しいチャットで、6か月分の振動を頼む |
| 4 | 過去の事例を探し、関係者に知らせる | Work IQを追加し、過去の事例を探して、自分宛てにメールを送る |

会社、設備、データはすべて架空のものです。

このLabはMicrosoftが公開している [microsoft/mcs-labs](https://github.com/microsoft/mcs-labs)（MIT License）のラボ「GitHub Copilot Harness - Component Model」（2026/11/3更新版）をもとにした日本語版です。Step 4は日本語版で差し替えた内容です。

### Step 3: 推論のトレースを読む（5分）

**このステップで行うこと:** 新しいチャットで、ツールが1回では返せない期間のデータを頼みます。推論の過程を開いて、失敗した呼び出しのあとにやり方を変えて進む流れを読みます。

1. ［新しいチャット］を選びます。Step 2の会話を持ち込まないためです。
2. 次の依頼を送ります。

   ```text
   WTG-114の振動を、過去6か月分見せてください。
   ```

3. 返答が返ってきたら、推論の過程の最初の「Used tool: query_telemetry」を選んで開きます。［入力］に頼んだ期間、［出力］にツールが返した内容が表示されます。

   **期待される結果:** 最初の呼び出しは、［出力］に「range_too_large」（1回で返せるのは90日まで）のエラーが返っています。

   ![最初の query_telemetry を開いた画面。［出力］の range_too_large のエラーが赤枠で囲まれている](../../assets/images/module3/15-uc3-trace-error.png)

4. 開いた項目を閉じ、続く推論の過程を読みます。

   **期待される結果:** エラーのあとに、期間を分けて query_telemetry を呼び直し、6か月分の推移を答えます。返答にも、期間を分けて取得したことが書かれます。

   ![推論の過程に query_telemetry が続けて並び、そのあとに振動の推移の返答が表示されている](../../assets/images/module3/16-uc3-retry.png)

> [!TIP]
> エラーを報告して止まったときは、`エラーの内容に従って、期間を分けて取り直してください。` と言い直します。

5. 講師の画面で、次の質問の結果を見ます。時間がある人は試します。データを2系列取得し、コードを実行するため、ほかより時間がかかります。

   ```text
   WTG-114について、過去60日間のギアボックス温度と発電出力をグラフにしてください。そのうえで、温度の上昇が負荷に連動しているのか、負荷とは無関係なのかを教えてください。
   ```

> [!TIP]
> グラフが返ってこない、計算せずに答えるときは `コードで実際に計算して、相関係数とグラフ（PNG）を返してください。` と言い直します。グラフの日本語が文字化けしたときは、`グラフの日本語が文字化けしています。日本語を表示できるフォントで作り直してください。使えるフォントがなければ、ラベルを英語にしてください。` と言い直します。

### Step 4: Work IQで過去の事例を探し、関係者に知らせる（10分）

**このステップで行うこと:** Work IQをツールに追加し、使うサービスをSharePointとOutlookのメールに絞ります。インストラクションに文面を足してから、新しいチャットで質問を4つ送ります。探す対象の資料は講師が事前にSharePointに置いたものです。ナレッジには追加しません。

1. 画面上部の［作成］を選びます。［ツール］の［＋］を選び、［ツールの追加］の［Work IQ］の［＋］を選びます。

   ![［ツールの追加］の画面。［Work IQ］の［＋］が赤枠で囲まれている](../../assets/images/module3/17-workiq-add.png)

> [!WARNING]
> 検索欄に「Work」と入力すると、［Work Orders MCP Server］も表示されます。別のツールなので、取り違えないようにします。一覧に表示されるOutlookやSharePointなど、サービスごとのツールも、Work IQの代わりには選びません。

2. ［接続を選択します］の画面で、［接続］に自分のアカウントが表示されていることを確かめ、［追加］を選びます。

   ![［接続を選択します］の画面。［追加］が赤枠で囲まれている](../../assets/images/module3/18-workiq-connection.png)

> [!NOTE]
> ［接続］に自分のアカウントが表示されていないときだけ、［接続］の一覧を開いて［新しい接続の作成］を選び、［作成］を選んでサインインします。そのあと［追加］を選びます。

3. ［ツール］に追加された［Work IQ］を選びます。［ツールを編集］の［Sources］で、［SharePoint］と［Outlook mail］だけを残します。［OneDrive］［Teams］［Calendar］［People］は、それぞれのチェックを選んで外します。［完了］を選びます。

   ![［ツールを編集］の［Sources］。SharePoint と Outlook mail だけにチェックが入っている](../../assets/images/module3/19-workiq-sources.png)

4. ［指示］の末尾に、次の文面を足します。保存のアイコンを選んで保存します。

   ```text
   ナレッジにない社内の資料や過去の経緯（過去の不具合の報告書、関係者とのやり取りなど）は、Work IQで探します。同じ型式の設備で前に起きたことは、いまの測定値を読む手がかりになります。

   メールの送信、予定の作成、チャットへの投稿は、担当者が宛先と内容を確認し、明示的に頼んだときだけ行ってください。
   ```

   ```text
   Aeris 3.2のタービンで、過去にギアボックスの振動が問題になった事例はありましたか。社内の資料から探してください。
   ```

   **期待される結果:** 推論の過程に「Used tool: ask」（Work IQ）が表示され、SharePointにある過去の事例の報告書を見つけて要約します。

   ![推論の過程の「Used tool: ask」が赤枠で囲まれている。返答の本文はぼかしている](../../assets/images/module3/21-uc4-workiq.png)

6. 同じチャットで、次の質問を送ります。

   ```text
   そのときの経過と比べると、今回のWTG-114はどの段階にありますか。対処限界値を超えてから何日たっているかも確かめてください。
   ```

   **期待される結果:** 報告書の内容に加えて、テレメトリのツールで振動の推移を確かめ、今回の段階を答えます。

   ![推論の過程に get_asset_status、query_telemetry、list_work_orders の「Used tool」が並び、赤枠で囲まれている。返答の本文はぼかしている](../../assets/images/module3/22-uc4-compare.png)

7. 同じチャットで、次の依頼を送ります。

   ```text
   この件は、基準に照らして、誰に、いつまでに知らせる必要がありますか。過去の事例にも触れた通知メールの文面を作って、まず私に見せてください。
   ```

   **期待される結果:** 出動基準に照らして通知先と期限を答え、メールの文面を表示します。メールはまだ送信しません。

   ![返答の最初の段落「メール文面は下に用意しました。まだ送信していません。」が赤枠で囲まれている。以降の本文はぼかしている](../../assets/images/module3/23-uc4-draft.png)

8. 同じチャットで、次の依頼を送ります。

   ```text
   その内容で、私自身のアドレス宛てに送ってください。
   ```

   **期待される結果:** 推論の過程に「Used tool: do_action」が表示され、自分のアドレス宛てにメールを送信したと返します。

   ![推論の過程の「Used tool: do_action」と、自分のアドレス宛てに送信したという段落が赤枠で囲まれている。アドレスと件名はぼかしている](../../assets/images/module3/24-uc4-send.png)

9. Outlookを開き、届いたメールを確かめます。

   ![Outlookで開いた、エージェントから自分宛てに届いた通知メール。件名は【S2・要対応】WTG-114で始まり、本文に状況と過去の事例との比較が書かれている](../../assets/images/module3/25-outlook-mail.png)

> [!TIP]
> 思ったとおりにならないときは、同じチャットで次のように言い直します。
>
> - Work IQを使わずに、事例はないと答える：`Work IQで、SharePointにある社内の資料を探してください。`
> - テレメトリを確かめずに答える：`テレメトリのツールで、WTG-114の振動の推移を確かめてから、比べてください。`
> - 文面を見せる前に送ろうとする：`まだ送らないでください。文面だけを見せてください。`
> - 宛先を聞いてくる：自分のメールアドレスを伝えます。
>
> 送信できないと答えるときは、管理者の設定で書き込みが許可されていない可能性があります。メールの文面を確かめたところで終えます。時間が足りないときは、手順6を省きます。

## まとめ

- インストラクションには範囲と、情報源どうしの関係を書きます。手順は書きません。
- どの情報源を使うかは、エージェントが部品の説明をもとに決めます。
- 推論のトレースを読めば、エージェントの判断を説明できます。
- ツールの失敗は止まる理由ではなく次の手を決める材料になります。そのために、ツールは対処のしかたが分かるエラーを返します。
- ナレッジは内容が決まった文書、ツールはシステムのいまの値と操作、Work IQはその人が見られる社内の情報です。メールの送信のような操作は、頼まれてから行わせます。
